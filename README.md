## Overview

TextDetect addresses a growing real-world challenge: distinguishing AI-generated content from human writing. The project combines classical NLP feature engineering with TF-IDF vectorisation, training a cross-validated Logistic Regression model on a balanced dataset of 130,000 human texts and 130,000 AI-generated texts.

The trained model is served through a lightweight Django web interface where any user can paste a text and get an instant prediction.

---

## ML Pipeline

### Dataset

- Source: [AI vs. Human Text dataset — Kaggle](https://www.kaggle.com/datasets/shanegerami/ai-human-text)
- Size: 260,000 samples (130,000 human / 130,000 AI-generated), balanced
- Label: `0` = human, `1` = AI-generated

### Feature Engineering

Three hand-crafted linguistic features are computed per text, then concatenated with the TF-IDF vector:

| Feature | Description |
|---|---|
| Punctuation % | Punctuation marks divided by total tokens × 100 |
| Linking words % | Frequency of connectors (*the, and, of, in…*) × 100 |
| Lexical reliability % | Proportion of content tokens (non-stop, non-punct) via spaCy |

### Vectorisation

TF-IDF (`TfidfVectorizer`) is fitted on the training corpus and serialised with `joblib`. At inference time, the saved vectorizer transforms the input text into a sparse matrix that is concatenated with the three hand-crafted features.

### Model

- Algorithm: `LogisticRegressionCV` (scikit-learn) — logistic regression with built-in cross-validated regularisation parameter search
- Parameters: `Cs=10`, `cv=5`, `max_iter=3000`, `random_state=42`
- Training: 80/10/10 train/validation/test split

### Inference Pipeline

```
Raw text input
      │
      ▼
spaCy (en_core_web_sm)  →  lexical_reliability %
NLTK word_tokenize      →  punctuation %
NLTK word_tokenize      →  linking_words %
      │
      ▼
TfidfVectorizer.transform()  →  sparse TF-IDF vector
      │
      ▼
np.concatenate([hand_crafted_features, tfidf_vector])
      │
      ▼
LogisticRegressionCV.predict()
      │
      ▼
"IA" (1.0)  /  "humain" (0.0)
```

### Serialised artefacts

| File | Role |
|---|---|
| `logistic_regression_model.pkl` | Trained `LogisticRegressionCV` model |
| `tfidf_vectorizer.pkl` | Fitted `TfidfVectorizer` (must match the model's training corpus) |

Both files are committed to the repository and loaded once at Django startup — no re-training required to run the app.

## Web Application

The Django app has two pages:

| URL | View | Description |
|---|---|---|
| `/` | `index` | Home page — project presentation |
| `/predict/` | `predict` | Text input form + prediction result |

The `predict` view accepts a `POST` with `text_to_predict` in the form body, runs the full inference pipeline, and renders the result inline on the same page.

## Setup & Installation

### Prerequisites

| Tool | Version |
|---|---|
| Python | 3.10+ |
| pip | any recent |

### Steps

```bash
# 1. Clone the repository
git clone https://github.com/thiernodaoudaly/ai-generated-vs-human-written-text.git
cd ai-generated-vs-human-written-text

# 2. Create and activate a virtual environment
python -m venv venv
source venv/bin/activate        # Linux / macOS
# venv\Scripts\activate         # Windows

# 3. Install dependencies
pip install -r requirements.txt

# 4. Download spaCy language model
python -m spacy download en_core_web_sm

# 5. Apply Django migrations (creates the SQLite session tables)
python manage.py migrate

# 6. Start the development server
python manage.py runserver
```

Open `http://127.0.0.1:8000` in your browser.

> **Note:** NLTK resources (`punkt`, `punkt_tab`, `stopwords`) are downloaded automatically on first run if not already present — no manual step required.

## Using the App

1. Go to `http://127.0.0.1:8000/predict/`
2. Paste or type any text in the textarea
3. Click **Predict**
4. The app displays whether the text was written by a **human** or an **AI**

**Example inputs to try:**

*AI-generated (likely):*
> "The utilisation of advanced computational methodologies enables the optimisation of resource allocation in complex multi-stakeholder environments."

*Human-written (likely):*
> "I wrote this at 2am after three coffees because the deadline was the next morning and I still had no idea what I was doing."

## Exploring the Notebook

`notebook.ipynb` contains the full training pipeline:

- Data loading and exploration (`AI_Human.csv` — not committed, download from Kaggle)
- Text cleaning and feature engineering
- TF-IDF vectorisation
- `LogisticRegressionCV` training with cross-validation
- Precision-Recall curve evaluation
- Serialisation of model and vectorizer with `joblib`

To re-run the notebook and re-generate the `.pkl` files:

```bash
# Download AI_Human.csv from Kaggle and place it at the project root
# https://www.kaggle.com/datasets/shanegerami/ai-human-text

pip install jupyter
jupyter notebook notebook.ipynb
# Run all cells
```

## Bugs Fixed (vs. original version)

The following issues were identified and corrected:

| File | Bug | Fix |
|---|---|---|
| `prediction/models.py` | `pd.read_csv("final_dataframef21.csv")` crashed at startup — file not in repo | Removed (not needed for inference) |
| `prediction/models.py` | `joblib.load("logistic_regression_model2.pkl")` — file not in repo | Points to `logistic_regression_model.pkl` (v1, present in repo) |
| `prediction/models.py` | Relative `.pkl` paths broke when Django wasn't started from the project root | Replaced with `os.path.abspath(__file__)`-based absolute paths |
| `prediction/models.py` | `spacy.load()` called on every request → ~500ms overhead per prediction | Loaded once at module level on startup |
| `ProjetML/settings.py` | `TEMPLATES DIRS: ["templates"]` — bare string, not a `Path` | Fixed to `BASE_DIR / "templates"` |
| `ProjetML/settings.py` | `STATIC_URL`, `STATICFILES_DIRS`, `DEFAULT_AUTO_FIELD` duplicated | Duplicate block removed |
| `requirements.txt` | No pinned versions — silent dependency conflicts between environments | Added version ranges per package group |
